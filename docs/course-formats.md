# Курсы LoLeS: редактор и переносимые форматы

## Как работает редактор для менеджера

1. Создать курс: название, описание, направление. Новый курс — черновик.
2. Добавить содержание: текст, видео, файл, ссылку или проверку знаний.
3. При необходимости добавить раздел (группу материалов), перемещать элементы кнопками вверх/вниз.
4. Создать тесты, просмотреть курс глазами учащегося.
5. Включить доступ учащимся в настройках курса.

Исходные курсы, модули и тесты сохраняются. Тип формата обмена не нужно выбирать при создании курса.

## Уже реализовано: безопасное хранение и обратный экспорт пакетов

SCORM и H5P теперь добавляются как обычный учебный материал в редакторе курса.
После выбора типа открывается общая библиотека с поиском по мере ввода названия
или тегов. Можно выбрать имеющийся пакет либо загрузить новый архив и назначить теги.
Пакет сохраняется один раз и может использоваться многими курсами; удаление исходного
курса не уничтожает содержимое, используемое другим курсом. Исходный ZIP/.h5p можно
скачать без изменений.

- SCORM: корневой imsmanifest.xml, XML, наличие структуры организаций и ресурсов, версии 1.2 / 2004.
- H5P: корневой h5p.json, content/content.json и объявленные библиотеки.
- Архивы до 100 МБ, до 512 МБ распакованного содержимого, до 10 000 записей; блокируются ../, абсолютные пути, симлинки и дубликаты.
- Архивы хранятся в приватном хранилище, не исполняются и не распаковываются в веб-каталог.
- Скачивание требует права просмотра курса и связи пакета с этим курсом.
  Хранится контрольная сумма SHA-256.
- При обновлении старые пакеты превращаются в обычные элементы содержимого
  в исходных курсах, без изменения файлов на диске.

Текстовые уроки редактируются TinyMCE 8, форматирование сохраняется после серверной
очистки HTML (HTMLPurifier). Есть списки, таблицы, ссылки и изображения по URL.

Это пока **не полноценный SCORM/H5P player/editor**. Проверка и хранение ZIP не означают соответствие SCORM или H5P runtime.

## Требования к дальнейшей полноценной реализации

### SCORM 1.2 / SCORM 2004

- Разбор manifest: вложенные SCO/items, ресурсы, точки входа, организации и зависимости.
- Изолированное исполнение в отдельном origin (не запускать загруженный JS рядом с cookie LMS).
- API 1.2 window.API и API 2004 window.API_1484_11, обработка Initialize/Finish, Set/Get, Commit и ошибок.
- Persist/restart попыток, suspend_data, lesson_location, scores, completion/success, objectives, interactions.
- Для 2004 — sequencing, navigation, rollup, версии 2nd/3rd/4th edition.
- Импорт оригинального пакета и его экспорт уже есть; экспорт собственных курсов в SCORM требует отдельного упаковщика.
- Тестирование со SCORM reference/conformance пакетами. Возможный JS runtime: scorm-again. Сам runtime не заменяет LMS-хранилище и правила sequencing.

### H5P

- Интеграция H5P Core + Editor и управление библиотеками/их версиями.
- Проверка зависимостей и прав установки библиотек, защита от недоверенных скриптов.
- Встраиваемый H5P editor/player, загрузка медиа, запись xAPI событий и результатов.
- Переносимость .h5p, включая отредактированные данные и все необходимые библиотеки.
- Два кандидата: официальный PHP H5P Core + Editor с интеграцией в Laravel либо sidecar на основе Lumi @lumieducation/h5p-server. Последний является библиотекой, не готовым самостоятельным сервисом.

## Архитектурные принципы

Менеджер должен видеть «материалы», «разделы», «тесты», а не SCO/CMI или формат базы. SCORM/H5P являются способами обмена контентом и интерактивного исполнения, а не обязательным типом всего курса.
