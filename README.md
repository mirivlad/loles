# LoLeS

**LoLeS (Local Learning System)** — самостоятельно размещаемая система управления обучением для учебных центров и организаций. Название проекта не ограничивает область его применения.

[![Container image](https://github.com/mirivlad/loles/actions/workflows/container.yml/badge.svg)](https://github.com/mirivlad/loles/actions/workflows/container.yml)
[GitHub](https://github.com/mirivlad/loles) · [GHCR](https://github.com/mirivlad/loles/pkgs/container/loles)

> **Статус:** разработка. Существующий интерфейс и бизнес-логика ещё нуждаются в аудите и доработке. Не используйте эту версию для реальных персональных данных или публичного интернет-сервиса без дополнительной проверки безопасности.

## Возможности текущего кода

- Предприятия, группы, пользователи и роли (администратор, менеджер, куратор, учащийся).
- Курсы, модули, категории, тесты и банк вопросов; единый каталог тестов по всем курсам.
- Индивидуальные и групповые назначения, заявки на обучение.
- Кураторы видят ведомости только своих предприятий, включая CSV,
  с проверкой прав на сервере; доступ к чужим учащимся и подгруппам закрыт.
- Прогресс по изученным материалам для каждого конкретного зачисления,
  ведомости результатов с разделением предприятий и физлиц, фильтры и
  выгрузка CSV. Итог требует нужного освоения каждого курса и всех
  обязательных официальных экзаменов (PROC-05). Сертификаты — отдельный этап.
- Экзамены с правилами для каждого набора: пробные/официальные,
  проходной порог в ошибках либо процентах, даты, таймер, лимит попыток,
  проверка множественного выбора, журнал и аннулирование с причиной (PROC-04).
  Сопоставление и упорядочивание вопросов будут поддержаны позднее.
- Программы из нескольких курсов, наборы с датами и вместимостью,
  заявки предприятий и физлиц, ручная отметка оплаты, атомарное зачисление
  и смешанные учебные подгруппы (новая модель PROC-01/02).
  Пока заявки принимает менеджер, отдельного публичного кабинета заявителя нет.
  Доступ зачисленных к курсам и тестам открывается в период обучения (PROC-03).

- Кабинет учащегося «Мои обучения», просмотр курсов, тестов и расписания.
- Русскоязычный интерфейс (в процессе доработки).

Полноценное прохождение тестов и отчётность о результатах **ещё не завершены**.

## Работа с курсами

Курс создаётся по названию и описанию, по умолчанию как черновик. Далее в редакторе
можно добавлять текстовые материалы, видео, файлы, ссылки, тесты и, при необходимости,
разделы. Порядок меняется кнопками вверх/вниз, без ручной нумерации. Доступен
предпросмотр глазами учащегося. Включение курса для учащихся — отдельная настройка.

В редакторе также появился импорт SCORM ZIP и H5P .h5p с безопасным хранением
и скачиванием идентичного оригинала. **Воспроизведение SCORM/H5P, создание
H5P-материалов, учёт событий и результатов пока не реализованы.** Не путайте
импорт ZIP с полноценной поддержкой стандарта. Детали, требования и следующие
этапы: [Курсы, SCORM и H5P](docs/course-formats.md).

## Docker / Portainer

Для LoLeS необходимы **два контейнера**:

| Сервис | Назначение |
| --- | --- |
| `app` — `ghcr.io/mirivlad/loles:latest` | PHP 8.5, Apache, Laravel |
| `db` — `mariadb:11.4` | База данных, не открывается наружу |

В `compose.yaml` уже описаны health checks, автоматические миграции и роли, настройки для Portainer и постоянные тома `db_data` и `app_storage`. При пересоздании контейнеров эти тома **сохраняются**.

### Вариант 1. Portainer (рекомендуется)

1. В Portainer откройте **Stacks → Add stack**. Укажите имя `loles`.
2. Выберите **Repository** (Git) и введите URL `https://github.com/mirivlad/loles`, ветку `refs/heads/main` и путь к Compose-файлу `compose.yaml`. Альтернативно можно вставить содержимое `compose.yaml` в Web editor.
3. В разделе **Environment variables** задайте следующие параметры (секреты генерируйте локально):

   | Переменная | Значение |
   | --- | --- |
   | `APP_KEY` | **Обязательно.** `base64:` + результат команды `openssl rand -base64 32` |
   | `DB_PASSWORD` | **Обязательно.** Случайный стойкий пароль без пробелов |
   | `APP_URL` | Адрес сайта, например `http://192.168.1.50:8088` или `https://loles.example.org` |
   | `LOLES_PORT` | Необязательно: порт хоста, по умолчанию `8088` |
   | `TRUSTED_PROXIES` | Необязательно: IP/CIDR доверенного обратного прокси |
   | `SESSION_SECURE_COOKIE` | `true` при использовании HTTPS |

   Пример генерации значений в терминале:

   ```bash
   printf 'APP_KEY=base64:%s\n' "$(openssl rand -base64 32)"
   printf 'DB_PASSWORD=%s\n' "$(openssl rand -hex 24)"
   ```

4. Нажмите **Deploy the stack**. После запуска обоих контейнеров приложение выполнит миграции и создаст системные роли. **Демонстрационные пользователи с известными паролями не создаются.**
5. Создайте первого администратора. В Portainer откройте **Containers → loles-app → Console**, выберите `/bin/sh`, подключитесь и запустите:

   ```bash
   php artisan loles:create-admin
   ```

   Введите имя, логин и пароль (email необязателен). После этого входите через `/login`. Саморегистрация отключена по умолчанию.

**Важно:** пароли и `APP_KEY` нельзя менять при обычном обновлении. При замене `DB_PASSWORD` в существующем томе MariaDB пароль пользователя базы автоматически не меняется; его необходимо изменить в самой БД. Потеря `APP_KEY` приводит к недействительности существующих шифрованных данных и сессий.

### Вариант 2. Docker Compose

Требуется Docker Engine и Docker Compose plugin.

```bash
git clone https://github.com/mirivlad/loles.git
cd loles
cp .env.docker.example .env
```

Отредактируйте `.env`, установите `APP_KEY`, `DB_PASSWORD`, `APP_URL` и при необходимости `LOLES_PORT`. Затем:

```bash
docker compose up -d
docker compose ps
docker compose exec app php artisan loles:create-admin
```

По умолчанию сайт доступен на порту **8088** хоста; если настроена другая переменная `LOLES_PORT`, используйте её. Docker не требуется собирать локально — используется готовый образ из GHCR.

### Обновление: Pull + Redeploy

Каждый push в `main` запускает GitHub Actions. Образ `ghcr.io/mirivlad/loles:latest` публикуется **только после успешных миграций, проверки HTTP-переадресаций и регрессионных тестов**. Дождитесь успешной сборки образа.

В **Portainer**: откройте **Stacks → loles → Editor / Update stack**, включите **Pull latest image** и выполните **Update / Re-deploy**. Названия пунктов немного зависят от версии Portainer. В стеке, созданном из Git, при необходимости также обновите конфигурацию из репозитория.

В **Docker Compose**:

```bash
git pull --ff-only
docker compose pull
docker compose up -d
```

Перед обновлениями с миграциями БД сделайте резервную копию. **Не используйте `docker compose down -v`** — флаг `-v` удаляет тома и данные.

### Резервное копирование

Для Docker Compose (из каталога проекта с настроенным `.env`):

```bash
docker compose exec -T db sh -c 'mariadb-dump -u"$MARIADB_USER" -p"$MARIADB_PASSWORD" "$MARIADB_DATABASE"' > loles-db.sql
docker compose exec -T app tar czf - -C /var/www/html storage > loles-storage.tar.gz
```

Сохраняйте файлы резервных копий вне хоста приложения; используйте права, ограничивающие доступ к содержимому резервных копий.

### HTTPS и reverse proxy

- Установите `APP_URL=https://loles.example.org`.
- Направьте reverse proxy на опубликованный порт LoLeS (обычно `8088`) и передавайте `Host`, `X-Forwarded-Proto` и `X-Forwarded-For`.
- Задайте `TRUSTED_PROXIES` как IP/CIDR **конкретного доверенного прокси**. Не используйте `*`, если приложение доступно напрямую извне.
- Установите `SESSION_SECURE_COOKIE=true`.
- Не публикуйте MariaDB в интернет. Ограничьте доступ к тестовому стенду через firewall/VPN.

### Диагностика

```bash
docker compose ps
docker compose logs -f --tail=150 app
docker compose logs -f --tail=100 db
docker compose exec app php artisan migrate:status
```

Если новый образ не скачивается, убедитесь, что сборка GitHub Actions завершилась, а GHCR-пакет `loles` открыт для публичного чтения (при необходимости **Package settings → Change visibility → Public**).

## Разработка

Технологии: PHP 8.5 для Docker (Laravel 13 поддерживает PHP 8.3+), Laravel (версия закреплена в `composer.lock`), Blade, MariaDB/MySQL, Spatie Laravel Permission, TinyMCE.

Для разработки без Docker понадобятся PHP и расширения из `Dockerfile`, Composer и MySQL/MariaDB. Настройте локальную `.env` на основе `.env.example`, затем:

```bash
composer install
npm ci
npm run build
php artisan key:generate
php artisan migrate
php artisan db:seed --class=RoleSeeder
php artisan loles:create-admin
php artisan serve
```

Запуск стандартного `DatabaseSeeder` создаёт только системные роли. Старый `UserSeeder` с тестовыми аккаунтами и общим паролем удалён. Демо-данные добавляются отдельной командой.

### Зависимости и совместимость

- Backend закреплён на стабильной ветке Laravel 13 (точные версии находятся в \`composer.lock\`); не используем \`dev-master\`. PHP-контейнер основан на поддерживаемой PHP 8.5.

- MariaDB 11.4 — поддерживаемая LTS-ветка. **Не меняйте образ БД на 12.3 автоматически на уже работающем томе:** сначала сделайте копию и отдельно проверьте обновление БД на тестовых данных.
- TinyMCE 8 распространяется в GPLv2+ режиме (\`license_key: 'gpl'\`). Перед использованием продукта как самостоятельной публичной open-source программы следует выбрать и явно оформить совместимую лицензию.
- Для локальной разработки фронтенда нужен Node.js 22 и npm. Изменения фронтенда после \`npm run build\` попадают в \`public/build\`, TinyMCE и FullCalendar копируются в \`public/\`. Созданные файлы не коммитятся.

## Демо-данные

Демонстрационные записи создаются только по явному запросу. При первом развёртывании
через Docker/Portainer установите LOLES_DEMO_DATA=true. После старта вы получите:
две организации, две учебные группы, шесть учащихся, вводный курс, тест и групповые
назначения. Все такие записи помечены словом «ДЕМО». Пароли генерируются случайно,
их можно просмотреть у менеджера и выгрузить для группы.

В уже работающем стеке выполните из консоли контейнера app:

    php artisan loles:demo-data --force

После первоначальной установки отключите LOLES_DEMO_DATA. Команда идемпотентна
и не создаёт повторные записи с теми же логинами. Не используйте демо-аккаунты
с реальными персональными данными.

## Учётные записи для учащихся

- Для входа используется только логин и пароль. Email не нужен.
- Логин можно задать в форме полного email-адреса, например
  `manager@company.ru`. Это имя для входа, а не подтверждение почтового
  ящика. Контактное поле Email по-прежнему необязательно.
  Для рабочих подходят короткие логины вроде `s00042`.

- В форме создания по умолчанию выбрана роль «Учащийся».
- Логин можно придумать или оставить пустым — например, будет создан s00042.
- По умолчанию формируется пароль из 6 символов без похожих знаков; при необходимости можно выбрать 8.
  При ручном вводе учащемуся можно задать пароль от 6 символов.
- Для сотрудников с повышенными привилегиями минимальная длина — 12 символов.
- На странице «Пользователи» администратор или менеджер может явно раскрыть
  выданные пароли учащихся и скопировать их. Для выбранного предприятия или
  учебной группы доступна выгрузка CSV, Excel (.xlsx) или Word (.docx) с ФИО, логином и паролем.
- Копия выданного пароля учащегося хранится отдельно, зашифрована ключом APP_KEY.
  Для проверки входа используется исключительно хеш. Пароли сотрудников
  и администраторов не включаются в ведомости.
- Пароль можно перевыпустить кнопкой с ключом. Выдачи и выгрузки фиксируются
  в журнале приложения без записи самих паролей.
- Ведомости CSV/XLSX/DOCX содержат конфиденциальные реквизиты: храните, передавайте и удаляйте
  файлы соответственно. Короткие пароли дополнительно защищены ограничением
  попыток входа; они не эквивалентны длинным паролям по стойкости.

Самостоятельная регистрация выключена. Её можно включить переменной окружения
LOLES_PUBLIC_REGISTRATION=true, но для учебного центра рекомендовано создавать
пользователей только менеджерами.

### Обновление существующего экземпляра

Старые аккаунты сохраняют пароли и email. При миграции логин выводится из
адреса до @ (при дубликатах формируется уникальный суффикс). После обновления
входите с новым логином, не с email. Его можно узнать в списке пользователей.
Перед миграцией базы сделайте резервную копию. Не меняйте APP_KEY: он нужен
для расшифровки реквизитов учащихся.


### Форматы ведомостей

В **Пользователи** (после выбора предприятия или группы) и на странице **Группы** кнопка
**«Скачать ведомость»** раскрывает меню:

- **Excel (.xlsx)** — оформленная таблица, фиксированная шапка, фильтры, текстовый формат
  логинов/паролей, подходящий для редактирования и учёта.
- **Word (.docx)** — таблица на альбомном листе для печати и выдачи куратору.
- **CSV (.csv)** — простой совместимый формат с разделителем «;» и UTF-8 BOM.

Для всех трёх вариантов применяются одни и те же фильтры и ограничения доступа.
Файл формируется на сервере по запросу, временные XLSX/DOCX удаляются после отправки.
Приложение не кладёт такие ведомости в публичный каталог загрузок.
Для Office-файлов используются библиотеки PHPOffice (точные версии в composer.lock).


### Библиотека SCORM и H5P, редактор текста

При создании текстового учебного материала открывается локальный TinyMCE 8
(WYSIWYG): заголовки, форматирование, списки, таблицы, ссылки, исходный HTML.
Содержимое безопасно очищается HTMLPurifier при записи и показе учащемуся.

SCORM и H5P добавляются там же, где остальные материалы: выбрать
«Добавить материал» → SCORM/H5P → найти уже загруженный пакет по названию/тегам
(результаты обновляются при вводе) → выбрать и сохранить. Или открыть «Загрузить
новый», выбрать архив и указать теги через запятую.

Один и тот же SCORM/H5P может использоваться в нескольких курсах без дублирования
архива. Старые архивы при миграции также появляются как элементы содержимого.
Удаление курса не удаляет общую библиотеку. Исходные архивы сохраняются для
скачивания/переноса; в этом этапе исполнение и оценивание SCORM/H5P ещё не
подключены, как и создание/редактирование самого H5P.


### Режим изучения и вложения в уроках

Вместо двухколоночного чтения курс открывается на отдельной странице
**«Содержание»** со списком разделов и учебных материалов.
Нажатие на материал открывает отдельную полноширинную страницу:
текст, видео/ссылка, документ, SCORM/H5P (пока заглушка исполнения)
или проверка знаний. Кнопки «Предыдущий», «Следующий» и
«К содержанию» всегда доступны; кнопка «Список материалов»
открывает выдвижную панель только по запросу, не занимая экран.

В редакторе менеджера теперь отдельная просторная страница для каждого
материала. TinyMCE имеет высоту не менее 650 px на обычном экране
и полноэкранный режим. Из редактора доступны:
- Загрузка и вставка изображений в текст без стороннего хостинга.
- Загрузка PDF, DOCX, XLSX, презентаций и других документов,
  вставка ссылки на скачивание в любом месте текста.
- «Прикреплённые файлы» — окно со списком, кнопками вставки,
  скачивания и удаления.
- Вставка картинки перетаскиванием или через меню TinyMCE.

Файлы находятся в приватном Laravel-хранилище, не в публичном /storage.
Для их получения необходима авторизация и назначение на курс (либо
роль редактора). Новые вложения, загруженные ещё до сохранения
текстового урока, закрепляются за ним при сохранении.

Шаги показывают позицию в последовательности, а не подтверждённое
завершение обучения. Полноценное прохождение тестов, а также runtime
SCORM/H5P с записью результатов развиваются отдельно.
